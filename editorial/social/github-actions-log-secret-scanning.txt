GitHub Secret Scanning Reaches Actions Logs

A secret can escape through CI/CD output even when no credential was committed to source code. GitHub's public preview scans completed Actions workflow logs for supported provider patterns and places findings in the repository's existing secret-scanning alert list, with a link back to the log.

The coverage boundary matters. The enterprise policy is off by default and applies only to eligible licensed repositories with secret scanning enabled. Only runs completed after activation are scanned. Generic, custom and AI-detected patterns are excluded, as are values already masked by Actions. During preview, these alerts do not generate notifications, so someone must check the alert list.

Our analysis follows the engineering response: identify sensitive workflows, review the logging path, assign alert ownership, and rotate credentials when an exposure is confirmed. Detection after a run does not replace preventing secrets from appearing in output.
