When a widely used library is found vulnerable, the first operational question is often not whether a patch exists. It is **where the package is present**, at which version, across which accounts and resources. An inventory that connects software components to deployed assets can shorten that initial search.

On [November 6, 2026](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-sbom-inventory/), AWS announced a software bill of materials inventory in Security Hub. Its November 9 weekly roundup highlighted the same launch. Security Hub builds the organization-wide view from SBOMs generated by Amazon Inspector for scanned EC2 instances, ECR container images and Lambda functions. The feature is included in Security Hub Essentials, populates where Inspector is enabled, and is available in AWS Regions where Security Hub is available.

## From component to resource

The SBOM page lists software packages with their versions, types and the number of resources on which each appears. Teams can filter or group by package attributes, account and region. A resource-detail view shows installed software on that resource; the inventory is also accessible through the Security Hub API. The ledger illustration above is conceptual, not a screenshot or a claim that Security Hub has that exact interface.

Imagine a newly disclosed dependency with several affected versions. A central team could first query the package and version range, then identify the associated compute resources and owners for triage. That is a useful bridge between a generic advisory and an actionable asset list. It can also help compare exposure across accounts without manually reconciling separate package lists.

But the meaning of a match must be kept precise. **Presence does not prove exploitability.** A package might not be loaded by an application, the vulnerable code path might be unreachable, or compensating controls might change the practical risk. Conversely, an absent inventory entry cannot prove absence of a package if Inspector has not scanned the relevant resource or SBOM coverage is incomplete.

## Measure the blind spots

Before relying on the new view for incident response, an organization should map which EC2 instances, ECR images and Lambda functions are covered by Inspector across accounts and regions, then compare that set against its expected asset inventory. It should check SBOM freshness, package identification and how findings are associated with deployed rather than merely stored images. AWS describes the inventory's behavior, but has not supplied an independent measure of its completeness in a particular customer's environment.

The engineering value is a faster route from *component* to *candidate affected asset*. Vulnerability reachability, business criticality and remediation priority still require additional investigation.
